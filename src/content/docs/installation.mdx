NQChart ships two ways:

1. **npm package** `@nqlib/nqchart` — versioned dependency (recommended for apps and this showcase).
2. **shadcn-compatible registry** — CLI copies chart source into your repo (typically `components/nqchart/`).

Agent **skills** are separate: they install markdown guidance for Cursor / Claude Code and do **not** copy chart files.

## Option A — npm (recommended)

<Steps>
  <Step>
    <StepTitle>Install the package and peers</StepTitle>
    <StepContent>
      <StepDescription>
        Add `@nqlib/nqchart` plus the runtime peers ECharts and Motion expect.
      </StepDescription>
      <CommandBlock commands={["@nqlib/nqchart", "echarts", "motion"]} />
      <StepDescription className="mt-4">
        Current line: **0.3.2**. Peer React 18/19. Independent of `@nqlib/nqui` — install any nqui version (or none); charts read CSS tokens when they exist.
      </StepDescription>
    </StepContent>
  </Step>

  <Step>
    <StepTitle>Import a chart entry</StepTitle>
    <StepContent>
      <StepDescription>
        Each family has a subpath entry. Compose children the same way as registry installs.
      </StepDescription>
```tsx
import {
  NQBarChart,
  Bar,
  XAxis,
  YAxis,
  Grid,
  Tooltip,
  Legend,
} from "@nqlib/nqchart/bar-chart";
import type { ChartConfig } from "@nqlib/nqchart";

const config = {
  desktop: {
    label: "Desktop",
    colors: { light: ["#047857"], dark: ["#10b981"] },
  },
} satisfies ChartConfig;

export function TrafficBars({ data }: { data: Array<{ month: string; desktop: number }> }) {
  return (
    <NQBarChart data={data} config={config} xDataKey="month" className="h-72 w-full">
      <Grid />
      <XAxis dataKey="month" />
      <YAxis />
      <Legend />
      <Tooltip />
      <Bar dataKey="desktop" />
    </NQBarChart>
  );
}
```
      <StepDescription className="mt-4">
        Other entries: `@nqlib/nqchart/line-chart`, `area-chart`, `funnel-chart`, `radial-chart`, … Recipes: `@nqlib/nqchart/recipes`.
      </StepDescription>
    </StepContent>
  </Step>
</Steps>

## Option B — shadcn registry

Use this when you want chart source owned inside your app (forkable copies).

<Steps>
  <Step>
    <StepTitle>Install Apache ECharts</StepTitle>
    <StepContent>
      <StepDescription>
        Install Apache ECharts and motion, the runtime dependencies for all chart components.
        
        Learn more at the <Link href="https://echarts.apache.org/en/index.html" _blank>Apache ECharts documentation</Link>.
      </StepDescription>
      <CommandBlock commands={["echarts", "motion"]} />
    </StepContent>
  </Step>
  
  <Step>
    <StepTitle>Setup shadcn/ui</StepTitle>
    <StepContent>
      <StepDescription>
        Initialize shadcn/ui in your project. This sets up Tailwind CSS, theme configuration, and `components.json`. Skip this step if you already have shadcn/ui installed.
        
        Check out the <Link href="https://ui.shadcn.com/docs/installation/next" _blank>shadcn/ui Next.js installation docs</Link> for more details.
      </StepDescription>
      <CliBlock action="init" commands={[]} />
    </StepContent>
  </Step>

  <Step>
    <StepTitle>Add the NQChart registry namespace</StepTitle>
    <StepContent>
      <StepDescription>
        Register the `@nqchart` namespace in your project's `components.json` so `shadcn add @nqchart/…` resolves. Skip if already configured.
      </StepDescription>
      ```json
      {
        "registries": {
          "@nqchart": "https://www.nqlib.com/r/{name}.json"
        }
      }
      ```
      <StepDescription className="mt-4">
        Alternative: install by full URL — `pnpm dlx shadcn@latest add https://www.nqlib.com/r/bar-chart.json`.
      </StepDescription>
    </StepContent>
  </Step>
  
  <Step>
    <StepTitle>Add chart components</StepTitle>
    <StepContent>
      <StepDescription>
        Replace `{chart-name}` with your chart type (e.g. `area-chart`, `bar-chart`, `line-chart`, `pie-chart`). Registry dependencies (`@nqchart/chart`, `@nqchart/tooltip`, etc.) install automatically.
      </StepDescription>
      <CliBlock commands={["@nqchart/{chart-name}"]} />
    </StepContent>
  </Step>

  <Step>
    <StepTitle>Optional — Chart recipes</StepTitle>
    <StepContent>
      <StepDescription>
        For histogram, Pareto, heatmap, bullet, gauge, and box plot patterns, install the shared data helpers. See [Chart recipes](/docs/chart-recipes) for usage.
      </StepDescription>
      <CliBlock commands={["@nqchart/chart-recipes"]} />
    </StepContent>
  </Step>
</Steps>

## Optional — Agent skill

**Not the same as chart install.** The [skills CLI](https://ui.shadcn.com/docs/skills) copies agent guidance into `.agents/skills/nqchart/` — when to pick each chart, compose children, theme colors, and BI recipes. It does **not** run `shadcn add` or copy React components.

Run from your **app project root**. Use `--list` to see available skills.

<SkillsBlock commands={["ctesibius/nqchart", "--skill", "nqchart", "-y"]} />

Canonical skill source: `skills/consumer/nqchart/` in the repo. Live docs on the nqlib showcase: [nqchart docs](https://www.nqlib.com/docs/nqchart) · [installation](https://www.nqlib.com/docs/nqchart/installation).
