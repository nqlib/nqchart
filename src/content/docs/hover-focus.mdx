Every NQChart uses the **same** hover behavior. There is one contract, applied
uniformly; individual charts do not invent their own hover animation.

## The contract

On hover — and on keyboard focus, and on legend isolate:

- The **focused mark group** stays at **full opacity**.
- **Every other mark dims to `0.2` opacity** (`FOCUS.dim`, also exported as
  `HOVER_DIM_OPACITY`).
- The change **fades over 120 ms** (`FOCUS.durationMs`, `cubicOut`) — one timing for
  every chart. Geometry never moves on focus (`animationDurationUpdate: 0`).
- **Nothing else changes** — no scale, no shadow "pop", no size jump. The focus
  mechanism is *opacity only*.

That's it. Whether it's a bar, a pie slice, or a radar polygon, the hovered thing
stays bright and the rest fade back. The single source of truth is
[`emphasis-presets.ts`](https://github.com/nqlib/nqchart/blob/main/src/registry/echarts-core/emphasis-presets.ts)
(`FOCUS`, the presets) and
[`hover-focus-repair.ts`](https://github.com/nqlib/nqchart/blob/main/src/registry/echarts-core/hover-focus-repair.ts)
(`focusMark` / `clearFocus`, the one entry point for pointer and keyboard).

## Every family

| Family | Mapping | Pointer & keyboard focus | Keyboard nav (with `onMarkClick`) |
| --- | --- | --- | --- |
| Bar, line, area, composed | Index focus | ECharts native | ← → categories, ↑ ↓ series |
| Monospace bar | Index focus | ECharts native | ← → categories, ↑ ↓ series |
| Waterfall | Index focus | NQChart repair (value bars) | ← → columns |
| Pie, donut | Item focus | NQChart repair | arrows walk slices |
| Funnel (classic) | Item focus | NQChart repair | arrows walk stages |
| Funnel pipe / rounded / cone / segmented | Item focus (custom series) | ECharts native | arrows walk stages |
| Treemap | Item focus | NQChart repair (hovered tile stays normal) | arrows walk leaf tiles |
| Scatter | Item focus (per row) | NQChart repair | arrows walk points |
| Radar | Item focus (per polygon) | ECharts native | arrows walk polygons |
| Heatmap, calendar | Item focus | ECharts native | arrows walk cells |
| Tile column | Item focus (custom series) | ECharts native | arrows walk columns |
| Radial bar, rose | Series focus | NQChart repair (whole ring / petal) | arrows walk rings / petals |
| Gauge, target | — | Tooltip only | — |
| Sparkline | — | Tooltip only | — |

"NQChart repair" families disable ECharts' own high-down (it races on adjacent marks)
and sync every mark of the family on each hover; keyboard focus goes through the same
repair, so it looks identical to hovering. Legend isolate (`<Legend isClickable />`)
dims to the same `0.2`.

## Why the blur shapes differ (they don't change the look)

Each chart dims through whichever style channels it actually draws —
`itemStyle` for bars and tiles, plus `lineStyle` for lines and radar polygons, plus
`areaStyle` for filled areas. This is **not** a stylistic choice: ECharts corrupts
bar columns if you blur their `lineStyle`, and throws if you blur
`areaStyle` on a lines-only radar. The opacity value (`0.2`) and the focus mode are
constant everywhere — only the channel that carries the opacity varies.

## The one sanctioned exception: `*-glow` variants

The explicit glow variants — `area-glow`, `scatter-glow`, `radar-glow` — add their
signature shadow to the focused mark on top of the opacity focus. This is a
**variant style**, opted into by name, not a hover animation. Default charts pass
no shadow and therefore never pop.

## Exceptions: tooltip-only charts

Two cases are **tooltip-only** — they show the tooltip on hover but do not dim:

- **Gauge / target** (single-row radial) — a single arc has no siblings to dim.
- **Sparkline** — decorative; emphasis disabled (its gradient area fill also can't be
  interpolated in a state transition).

Radial bar / rose used to be tooltip-only: per-item focus flickered across the ring
gaps. **Series focus solves it** — modeling each ring as its own series means
`focus: "series"` never hit-tests per item. The 120 ms fade only interpolates
opacity, so gradient ring fills fade safely too.

## Flicker control

HTML tooltips render over the canvas. To stop the pointer from ever landing on the
tooltip DOM (which would bounce hover on/off), the tooltip is `pointer-events: none`,
offset from the cursor, and uses `transitionDuration: 0`. See
[`echarts-tooltip.ts`](https://github.com/nqlib/nqchart/blob/main/src/registry/echarts-core/echarts-tooltip.ts).

## Opt out

The contract is **on by default**. Existing apps that omit the prop keep today’s dim.

Pass `hoverFocus={false}` on any `NQ*Chart` root to keep the tooltip and skip sibling fade — for the pointer **and** for keyboard focus (arrow keys still move the tooltip). Legend isolate (`<Legend isClickable />`) and the brush are separate switches.

```tsx
<NQAreaChart hoverFocus={false} data={data} config={config} xDataKey="period">
  <Grid /><XAxis dataKey="period" /><Legend /><Tooltip />
  <Area dataKey="home" />
</NQAreaChart>
```

Sparkline and single-arc gauge stay tooltip-only either way — they have no siblings to dim.

## Adding or changing a chart

1. Pick the mapping by geometry: shared category axis → `cartesianColumnFocus` /
   `cartesianLineFocus`; per-point item charts (pie, scatter) → `itemFocus`; polar rings → `radialBarSeriesFocus`.
   Every preset carries the `FOCUS` timing; never hand-write `stateAnimation`.
2. If ECharts' own high-down is wrong for the family (flicker, vanish, stale bright
   marks), add an adapter in `hover-focus-repair.ts` rather than a new module. Only if
   the 120 ms fade itself brings a regression back, list the family in
   `FOCUS_INSTANT_FAMILIES` and cite the fix note.
3. Do **not** add `scale`, `shadowBlur` (unless it's a `*-glow` variant), or any
   other hover transform. If a chart "needs" something different, the contract
   changes here first — in this doc and `emphasis-presets.ts` — for **all** charts,
   not just one.
